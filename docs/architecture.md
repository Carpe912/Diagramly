# Diagramly 架构与扩展设计

编辑器使用 Vue 3、TypeScript 和固定版本的 maxGraph，后端使用 Fastify、PostgreSQL。标准 JSON 文档是唯一图形数据源，内部不依赖 XML；XML 只负责可选文件交换。不兼容旧业务数据，不依赖 Coopwire 运行时。

## 文档与投影

领域模型位于 src/domain，既不导入 Vue，也不导入引擎。文档分为 nodes、entities、edges：节点保存形状与布局，实体保存业务属性和表单，连线引用稳定节点 ID。每个业务节点和实体具有独立 ID，复制创建新身份。

图形注册表 src/shapes/registry.ts 定义类型、默认尺寸、端口和组合布局。活动的头、正文、底部等部件只存在于引擎投影中，其内部 Cell 不是可独立操作的业务对象。引擎适配器位于 src/adapters/maxgraph，负责渲染及将拖动、连线、缩放等事件转为领域命令。

新增图形时先扩展注册表；需要新业务字段时再扩展实体 Schema、领域校验与表单。不要在界面直接 insertVertex 创建业务节点，也不要将 DOM、可执行脚本或 Vue 响应式对象存进 JSON。

## 编辑与持久化

所有编辑经过 Editor 命令入口。执行顺序为严格 Schema 校验、命令去重、revision 检查、应用草稿、整体验证、一次提交与历史记录。批量编辑只有一个撤销步骤；撤销和重做保持业务 ID，并递增文档 revision。只读文档在命令入口拒绝修改，后端独立执行权限校验。

本机文档写入 IndexedDB。服务端文档同时保留本机草稿，由 DocumentSync 串行提交完整 JSON，使用独立的服务端 revision 乐观锁。任何不确定响应或冲突停止后续提交，不盲目重试。重新打开时用户可选服务端版本或另存本机草稿；没有自动合并或实时多人协同。

后端当前文档和历史快照在同一 PostgreSQL 事务中写入。恢复快照创建新版本；回收站操作也校验版本。UI 撤销历史与服务器持久版本是两种不同机制。

## 自有业务模块

活动表单位于编辑器内部，输入输出、异常、痛点和关联 ID 属于文档实体 resources。共享目录、数据表字段、附件、账号与讨论由独立服务管理。业务目录使用记录级 revision；目录修改与文档修改不是跨接口事务。

讨论关联 documentId 和 nodeId/edgeId，图形删除后保留原讨论。流程体检是领域纯函数，检查结构问题而非证明业务逻辑正确。附件存储于数据库，备份包含附件内容。历史仍引用的资源不可删除。

账号权限覆盖整个工作空间，分管理员、编辑者、只读用户，不含文档级 ACL。Agent 实验入口不在本轮扩展范围。

## 运维与验证

部署说明见 [独立服务与运维](standalone-server.md)，表单说明见 [自有业务详情](activity-details.md)。旧接入文档仅为历史研究资料。

升级 maxGraph 时保留领域文档格式，集中调整引擎适配器，运行类型检查、命令测试和真实浏览器绘图回归。schemaVersion 和 shapeVersion 独立演进，未知文件版本直接拒绝。
