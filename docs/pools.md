# 泳池与泳道

## 使用

图形库顶部「容器」提供水平泳池和垂直泳池。新泳池默认创建两条泳道；选中泳池后，通过泳池工具栏添加泳道。角色在泳道工具栏中选择。

- **水平泳池**：泳池标题竖排在左侧；泳道按行排列，泳道标题位于左侧。
- **垂直泳池**：泳池标题横排在顶部；泳道按列排列，泳道标题位于顶部。
- 选中泳池标题或边框时显示泳池工具栏；选中泳道时只显示独立的泳道工具栏，可调整颜色和组织角色。
- 工具栏可添加泳道、选择并删除泳道、切换方向、修改背景、标题背景和文字颜色。
- 泳道双击和 F2 不进入名称编辑，属性中的名称只读。通过「角色泳道」或属性中的组织角色选择更新名称，多角色名称以顿号连接；清空角色后显示「角色泳道」。已有文档名称在重新选择角色前保留。
- 有活动的泳道删除前会显示节点数量并确认；至少保留一条泳道。删除整个泳池会级联其泳道、节点和连线，作为一次撤销步骤。
- 在泳道属性中选择「所属泳池」可跨泳池移动泳道，保留活动、角色和连线。目标方向不同，标题与内容布局随目标泳池变化。
- 活动和基础节点可以直接拖入其他泳道。以图形中心识别目标泳道，按目标内容区换算相对坐标，靠近标题或边缘时自动吸附到合法位置；目标过小时扩展泳池。多选拖动一次提交，位置、归属和容器扩展可一起撤销。业务 ID 与连线保留，远程模式会同步目标泳道的组织角色；落到所有泳道之外时仍保留边界校验。
- 拖动泳池移动整体；拖动边框或修改属性可调整泳池尺寸。泳道 X/Y 由泳池控制；可拖动右侧、底部和右下角手柄调整宽高，泳池自动跟随。共享尺寸会同步到同池其他泳道，过小会遮挡任一泳道内容的操作会整体拒绝。属性中也可编辑宽高。

泳池颜色作为泳道默认值；泳道工具栏设置的独立颜色优先，后续修改泳池颜色不会覆盖这些设置。活动卡片保持自身外观，不继承泳池背景或文字颜色。

## 结构与约束

```text
pool-horizontal / pool-vertical
  ├─ swimlane (laneOrder: 0)
  │   ├─ activity
  │   └─ decision
  └─ swimlane (laneOrder: 1)
      └─ activity
```

泳池、泳道都是真实文档节点，各自拥有独立业务实体；标题和背景部件仍是派生视图。泳池只能位于画布顶层，直接子节点只能是泳道。泳道不能再嵌套容器；活动只以泳道为父节点。所有子坐标相对父节点保存。

`laneOrder` 是泳池内连续且唯一的顺序。`src/domain/pools.ts` 统一计算尺寸和布局，命令、导入校验与 XML 转换共用规则。泳池标题宽/高为 36px；水平泳道内容区左侧预留 80px，垂直泳道顶部预留 52px。缩小后会遮挡活动或覆盖标题的操作整体失败。

方向切换会按流程关系重新分层布局：水平泳池的同泳道流程从左到右，垂直泳池从上到下；跨泳道交接尽量放在同一列／同一行，分支按图形实际尺寸留出间距，回退线使用内容外侧的通道。连接点会随方向重选，例如水平泳池中的下→上交接，切换为垂直泳池后改为右→左交接。开始和结束节点支持四个方向，原有 out／in 端口保持兼容。

方向切换保留图形尺寸、节点／连线 ID、泳道归属、实体、业务引用、连线文字及配色和箭头样式；路径统一使用正交路由。布局、连接点和泳池尺寸作为一次命令提交，可整体撤销重做。它不会适应画布或改变缩放比例。回退通道按当前几何实时计算，画布、XML、PNG 共用，节点移动后不会残留固定折点。泳道移动、增删和尺寸变化同样可整体撤销；创建或复制活动时如内容空间不足，会按布局规则扩展泳池。

## 命令

界面、Agent 与远程模式共用以下命令：

```json
{
  "commandId": "cmd_pool_example",
  "expectedRevision": 0,
  "origin": "agent",
  "label": "调整泳池",
  "operations": [
    { "type": "pool.orientation", "id": "pool_order", "orientation": "vertical" },
    {
      "type": "pool.lane.add",
      "poolId": "pool_order",
      "laneId": "lane_review",
      "entityId": "entity_review",
      "name": "审核团队"
    },
    {
      "type": "node.appearance",
      "id": "pool_order",
      "fill": "#eaf4ee",
      "headerFill": "#bddac8",
      "fontColor": "#315342"
    }
  ]
}
```

另支持 `lane.roles.set`，以 `{ laneId, roles: [{ id, name }] }` 同时更新角色引用和泳道名称；远程模式要求角色来自当前项目选项。普通 `node.update` 不能直接修改泳道名称或角色 ID，界面与 Agent 共用此约束。

另支持 `pool.lane.remove`、`pool.lane.move`、`pool.lane.resize`。`Editor.createPool` 生成泳池和默认泳道的完整操作批次；普通 `node.create` 单独创建一个无泳道泳池会被最终文档校验拒绝。

## 旧文档与远程

读取第一版只保存独立泳道的本机文档时，`upgradeStandaloneLanes` 补充泳池，保留泳道、活动与连线 ID。读取旧 Coopwire XML 时，识别 horizontalSwimlane / verticalSwimlane、泳池归属、角色和颜色，保留原始 XML 备份，不再将所有泳道打散成顶层节点。

JSON、Coopwire 兼容 XML、规范化元数据及 PNG 共用当前布局与颜色投影。远程模式下修改方向、泳道和颜色通过原有流程保存接口持久化；纯图形调整不触发无关活动的 updateAct。永久业务删除语义保持不变。

未实现泳池复制和任意容器嵌套。布局优先保持数据及连线身份，方向转换不是业务流程的自动排版算法。
